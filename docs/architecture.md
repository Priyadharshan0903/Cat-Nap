# Architecture

One repository, one statically deployed application. React + TypeScript runs entirely on the device; Vite creates the GitHub Pages bundle. Motion animates placement and short celebrations. Single taps save an X immediately; a second tap within 330ms on the same cell promotes the original pre-gesture board into a cat placement. The pair occupies one undo step. Keyboard C/X controls remain explicit. SVG cats and room artwork are original code-native assets. Manrope is bundled for offline use.

The puzzle engine has no React or storage dependencies. An exact row-by-row solver verifies uniqueness; a separate deduction engine applies singles and shared exclusions across rows, columns, regions, and no-touch neighborhoods. Only boards fully solvable by that deduction engine enter the pack. Teaching hints in `lib/coaching.ts` expose one exclusion at a time: locked colors/lines, two-unit reservations, or shared no-touch exclusions. They ignore player X marks as premises, request a review when all possible homes have been crossed out, and never offer a cat placement. An optional action marks the excluded cells. Find a cat remains the direct placement assist. The default game shows rule conflicts but permits experimentation, with an 80-move undo history and free assistance refills.

Levels are immutable data identified by stable IDs. The current 120-board pack goes from 5×5 to 9×9. Difficulty labels currently correspond to size. Daily boards deterministically transform validated pack boards using the device-local date.

Progress is a versioned JSON-compatible document. Games are keyed by level and device ID (plus a fork suffix when needed), with monotonic per-branch revisions. Merge unions achievements, retains earliest completion and fastest time, and preserves separate board branches. The newest updated branch resumes by default; users can choose an alternative in Settings. Timestamps order independent-device branches; clock skew can affect the default choice but cannot delete the other branch. Import explicitly opens the backup’s last puzzle and selected board, even when local settings are newer. Continuing an imported board forks it when needed to preserve an existing local alternative. Repeated imports reuse an unchanged local copy. Subsequent writes advance beyond the loaded timestamps, so the selected board resumes after reload.

A synchronous localStorage journal records each move before returning from the interaction. A serialized Dexie write records an independent IndexedDB copy. Startup validates and merges the copies. Saving status reflects successful persistence to at least one store. A service worker versions the complete compiled release, keeping offline HTML and assets consistent. Data is never stored in the service-worker cache; releasing an update preserves saves.

The application never sends progress to a server. Export/import is an explicit manual transfer. No accounts, backend services, runtime secrets, trackers, or APIs are needed. Browser/origin boundaries apply: different browsers, local preview versus production, and some installed iPhone web apps have independent storage. Export before changing origins.

Future automatic sync could be added behind the storage layer, with authentication and conflict handling. GitHub Pages itself cannot provide that backend. It is intentionally outside this version's scope.

The v1 save schema now accepts optional reward, star, and attempt-assistance fields. Legacy saves remain readable. Completion entitlements are derived from the union of completed puzzle IDs, so replays and duplicate imports cannot mint rewards. Spending/refill counters merge by per-device maxima and sum across devices. Starter credit is one constant shared across merged saves. Attempt hint receipts avoid charging again for an already revealed deduction. Star upgrades happen only on a real solve transition, never on a timer save or when opening an already solved legacy board.

The chapter map uses a scaled SVG route with real HTML level buttons, stars from saved completion records, the selected cat marking the current puzzle, and chapter gifts computed from the same completion data as the wallet. All regular levels remain open. Region coats are deterministic and distinct for all nine possible region IDs; companion selection remains independent.

The v1.2 preferences add optional theme and dragMark fields without changing the v1 save version. Garden, Seaside, Night, and live device light/dark selection style the surrounding interface; region colors remain stable. Pointer strokes preview X marks until release, preserve cats and existing marks, interpolate quick movements, and commit as one undo step. Pointer cancellation, blur, and visibility changes discard unfinished previews. Dragging can be disabled to allow touch scrolling over the board. Existing click/double-tap and keyboard paths remain separate.

A region settles when its cat matches the validated solution and has no rule conflict. A brief wash, happy face, and small completion indicator confirm the placement without blocking input. This is positive correctness feedback on player placements; hints still never reveal or place a cat. Reduced-motion preferences disable the new movement. Hint focus dims unrelated cells with a scrim. Explanations name the colors and show matching swatches; hints do not force corner numbers. The optional region-number accessibility preference remains available. Generic observation hints are free; new actionable deductions retain the existing token/receipt rules.

Backups are plain v1 JSON with matching 16 MB export/import bounds. Download anchors are attached to the document and blob URLs survive for 60 seconds for Safari. Import uses File.text or FileReader, validates known puzzle IDs and board bounds before mutation, then merges achievements, rewards, settings, and board branches. A persistent Settings status reports success or errors; import completion waits for the resulting snapshot’s persistence attempt.
